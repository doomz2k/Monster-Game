# Project workflow

- Work on `main` in `doomz2k/Monster-Game`.
- Whenever a project change is saved in the local workspace, commit it and push it to GitHub `main`. Make small, coherent commits as work progresses; do not leave completed changes only in the local workspace.
- Run checks appropriate to each change before pushing.
- This is standing user authorization to commit and push project changes to `main`; no additional conversational confirmation is needed for routine commits and pushes.
- If a commit or push fails, resolve it where possible and clearly report any changes that remain unsynced. Never force-push or overwrite unrelated work to satisfy this rule.
